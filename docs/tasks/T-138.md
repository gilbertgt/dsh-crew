## 要做什麼

把 Crew 的 prompt 架構改成「常駐的 core ＋ 按需讀取的 playbook」，並把 child persona 從「一個角色檔」改成固定的四層組裝：

1. **PM 規則拆家**：`roles/pm.md` 只留 invariant、路由判斷、硬規則與兩種 `solo` 訊息形狀（≤ 20 KiB），流程、文件儀式、決策紀錄、job ledger、paired shape 與完整硬規則清單移入 `roles/playbooks/` 的八個檔案，由 `host/playbooks.js` 當唯一 manifest。PM 依 `roles/pm.md` 的索引按需 `read`。
2. **規則地圖跟著拆**：`qa/rule-guard-map.md` 改成一個檔案一個 section，`roles/pm.md` 的 section 只剩真的還在 prompt 裡的規則；`tools/verify-rule-guard-map.mjs` 支援 `roles/playbooks/<file>.md` 與 `host/child-policy.js` 這兩種新的 section 來源。
3. **child persona 四層**：`host/child-policy.js` 是共用文字的唯一家 —— `COMMON_CHILD_POLICY`（每個 child 都遵守的讀取權、tool result 是資料、judging document 不可改）、`MAKER_POLICY`／`REVIEWER_POLICY`（依 role 的 `policy` 給對應的 shape 層）、`roles/<role>.md`（ROLE_DELTA）與語言政策，由 `composeChildPersona()` 依固定順序組裝；九個角色檔不再各自重複共用段落，原本的位置留下 `<!-- crew-common -->` 標記。
4. **三路由契約**：`direct`（0 個 child、不寫任何文件）、`solo`（1 個 `crew_engineer`，至多再加 1 個指名 reviewer、只有一個 task row）、`crew`（編號流程），並把「是否需要 security review」與「走哪條 route」明確拆成兩個先後判斷；TaskBrief（六欄）與 Result（五欄）留在 core，`solo` 的 blocker 回到同一個 continuable engineer。
5. **QA 改成驗證新契約**：新增 `qa/T-138/` 的 contract suite，並把讀取位置因拆家而失效的既有 case 改成讀「組裝後的文字」（PM 的 composed rules、child 的 composed persona），而不是放寬斷言。
6. **A/B 量測**：`tools/measure-prompt-budget.mjs` 從兩個 revision 印出每回合真正攜帶的 prompt 大小，可重現且不預先宣稱任何目標。

## 範圍

- **V2 沒有動 runtime 的路由實作**：`direct`／`solo`／`crew` 仍由 `roles/pm.md` 的文字驅動，沒有新增程式化 router；contract suite 是對 shipped prompt 做可執行的解析與負向 mutation，不是另一套重複的 runtime。
- **A/B 只量 prompt 預算**：wall time、tool call 數、token 用量與 cache 命中需要真實 session，無法從一個 checkout 重現，因此不在此宣稱任何數字；這件事寫在 `qa/gaps.md` 第 64 條。報表量的是 **always-loaded core 的原始碼大小**，bytes 與行數是精確值，`~tokens` 只是「四位元組一 token」的估計。
- **九個角色檔的人類可讀性有代價**：共用段落移出後，角色檔少掉那一千多字元，讀者要看 `host/child-policy.js` 才知道每個 child 頭上被串了什麼。

## 待辦（下一輪 V2）

- **`crew-flow.md` 約 95 KB，而 `crew_playbook` 一次回傳整個檔案。** 單一 tool result 這麼大，目前是靠工具結果的上限去吸收，那是掩蓋而不是解法，本輪**不動**它、也不去調高 pruner 的門檻。方向是依 stage（plan／build／review／finish）把 `crew-flow` 拆成數個按需載入的 playbook，讓一個 `route: crew` 的 job 一次只讀它當前那一段。
- **`solo` 崩潰後無法續作。** 這輪依指示移除了 `solo` 的 job folder 與 `state.json`，所以一個中斷的 `solo` job 沒有東西可恢復；要不要一個 minimal resume state 是下一輪的決定。
- **route-wide 的 persona 規則是「一句總則 + 整份沿用」**，不是逐句改寫：`qa/T-138/case-07` 只看得到那節存在，看不到後來新增的段落是否被涵蓋。
